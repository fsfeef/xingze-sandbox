# 一栋一栋对标 — 星泽市 vs 参考沙盘（formulasearch）

日期：2026-11-26；B 路产出（方案 v3，§3.3 对标、§3.4① 改名、§3.15 风控；验收表第 4、5、16 行；2026-11-26 13:47–13:56 改向后修订版）。
对照源：参考沙盘 `https://digital-twin-sandbox.pages.dev/`（成都中心城区数字沙盘）。**对照源只用参考沙盘，不用卫星地图。**
风格口径（林萧 2026-11-26 13:50/13:51）：风格标签只用**游戏画面风格**——亮闪闪、未来城市感、霓虹、发光窗、雨后反光，做法不变（方案 §4 色板照用）。
顺序口径（林萧 14:02）：**先白模、后贴图**——他那个有的一环，我们的一环先照着他那个完全贴出来，白模好了再去贴图。24G GPU 那台他已开好（按时间计费），FLUX 贴图等白模一环贴完再上，由 A 路执行。
高度口径（林萧 13:49）：高度照我们算过的做——**层数×3.2 + OSM 标签**；房顶结构照他那个做（圆角还是棱角、什么角都照他的图），不再做成方块圆柱体。
体形口径（林萧 13:48）：现在的楼都是圆柱体、方块简单体块，**一栋一栋改**——退台、坡顶、幕墙、转角、裙楼，先从抽查 20 栋 + 25 地标开始。对标卡因此是五项：屋顶、体形、立面、高度可信度、街面，体形是 13:48 的头号项。
比例口径（林萧 14:11）：他那个里面有些比例不对，照抄时比例错的地方要修对，不能把他的错也搬过来（339 塔就是一例）；建筑照着人家的弄；铁路怎么画、树怎么种、路怎么画、桥怎么建，里面都有，全去照着弄——卡里的改法按这个口径：体形照他的方法，比例按我们核实过的数。
配色口径（林萧 14:03）：人家楼顶、路到底怎么画，哪里用深色砖、哪里用青瓦，都看清楚了再画——**先对着参考站截图出配色表再动手**。参考截图还没到，配色表本轮出不了，卡里只写做法方向。

## 0. 参考那边已知什么（方案 §1 + 附录 B，主聊天浏览器实测 2026-11-26 13:33–13:42）

- 楼**有皮**：窗格、阳台、砖墙、瓦顶、红灯笼；近看作者自己承认不行。
- 街面**无人、无开张商铺**，地面大面积平灰石板；车是简易方块小车；树是低多边形团块。
- 339 塔也是错的：标签 339m，模型 113m 级，和我们一样。
- 小地图四种模式下都找不到；全站无开车入口；热力俯瞰几乎看不见、街面有漂浮蓝白雾团。
- **参考栏“待补”说明：参考那边的逐栋截图主聊天正在用浏览器跑，还没到。**本报告所有卡的“参考”栏一律写“待补”，不编参考数据，不干等。截图到了，逐卡补齐（配色表随之出）。

- 我方截图：headless Chromium（SwiftShader，`window.__sandbox` 直接定航拍目标），本地服务 `http://localhost:8000/app/`，10:00 白天。地标 dist 380m / el 0.55；抽查点 dist 500m / el 0.5。脚本 `/tmp/benchmark-shots.js`（两次补拍 `/tmp/benchmark-shots2.js`），截图目录 `tests/benchmark/`。
